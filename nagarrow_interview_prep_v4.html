Two Sum — Find two numbers that add up to a target
▼
Problem: Given array [2,7,11,15], target=9 → return [0,1] (2+7=9)

Brute Force — O(n²): Check every pair

def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i+1, n):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

# Time: O(n²)  Space: O(1)
Time: O(n²) Space: O(1)
Key Insight: Use a HashMap. For each number, check if (target - num) already exists in the map. If yes → found! If no → store num with its index.
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []

# Example: nums=[2,7,11,15], target=9
# i=0: complement=7, not in seen, store {2:0}
# i=1: complement=2, found! return [0,1] ✓
Time: O(n) Space: O(n)
Pattern to Remember: Whenever you need to find a pair with a condition → think HashMap first. "Store what you've seen, check what you need."
Cross Questions Hitesh/interviewer will ask:
  • What if the array has duplicate numbers? → HashMap handles it (stores latest index)
  • What if there are multiple valid pairs? → Return all pairs: collect all into list
  • What if the array is sorted? → Use two-pointer approach, O(n) time O(1) space
  • Can you solve it without extra space? → Yes if sorted: two pointers. If unsorted: O(n²) brute force only
  • Why did you choose HashMap over sorting+two-pointer? → Sorting changes indices. HashMap preserves original indices.

Move Zeroes to End — without changing order of non-zero elements
▼
Problem: [0,1,0,3,12] → [1,3,12,0,0] (in-place, maintain relative order)
def move_zeroes_brute(nums):
    # Collect non-zeros, then fill zeros
    non_zero = [x for x in nums if x != 0]
    for i in range(len(non_zero)):
        nums[i] = non_zero[i]
    for i in range(len(non_zero), len(nums)):
        nums[i] = 0

# Time: O(n)  Space: O(n) — extra array used
Time: O(n) Space: O(n)
Key Insight: Two pointers. write pointer tracks next position for non-zero. Walk read through array — whenever you see non-zero, write it to write position, advance both.
def move_zeroes(nums):
    write = 0  # position to write next non-zero
    
    # Pass 1: move all non-zeros to front
    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write] = nums[read]
            write += 1
    
    # Pass 2: fill rest with zeros
    while write < len(nums):
        nums[write] = 0
        write += 1

# [0,1,0,3,12] → write=0
# read=1: nums[1]=1≠0, nums[0]=1, write=1
# read=3: nums[3]=3≠0, nums[1]=3, write=2
# read=4: nums[4]=12≠0, nums[2]=12, write=3
# fill: nums[3]=0, nums[4]=0 → [1,3,12,0,0] ✓
Time: O(n) Space: O(1) — in-place!
Pattern: "Write pointer" technique — used for partitioning arrays in-place. Same pattern used in Remove Duplicates, Remove Element problems.
Cross Questions:
  • Can you do it with fewer writes? → Yes: swap instead of overwrite — only swap when nums[read]≠0 and read>write
  • What if you need to move non-zeros to end instead? → Reverse the logic, walk from right
  • What is the minimum number of operations? → Depends on number of zeroes. Can't do better than O(n).

Maximum Subarray Sum — Kadane's Algorithm
▼
Problem: [-2,1,-3,4,-1,2,1,-5,4] → 6 (subarray [4,-1,2,1])
def max_subarray_brute(nums):
    max_sum = float('-inf')
    n = len(nums)
    for i in range(n):
        curr = 0
        for j in range(i, n):
            curr += nums[j]
            max_sum = max(max_sum, curr)
    return max_sum

# Time: O(n²)  Space: O(1)
Time: O(n²)Space: O(1)
Key Insight (Kadane's): At each position, decide: is it better to extend the current subarray, or start fresh? If current sum goes negative → restart from current element.
def max_subarray(nums):
    curr_sum = nums[0]   # current running sum
    max_sum = nums[0]    # best seen so far
    
    for i in range(1, len(nums)):
        # Either extend existing subarray OR start new one
        curr_sum = max(nums[i], curr_sum + nums[i])
        max_sum = max(max_sum, curr_sum)
    
    return max_sum

# Trace: [-2,1,-3,4,-1,2,1,-5,4]
# curr: -2 → 1 → -2→4 → 3→5→6→1→5
# max:  -2 → 1 → 1→4 → 4→5→6→6→6 ✓
Time: O(n)Space: O(1)
Kadane's in one line: curr = max(num, curr + num) — if adding the current element makes things worse than starting fresh, restart.
Cross Questions:
  • Can you also return the subarray itself (not just sum)? → Track start/end indices when curr_sum resets and when max_sum updates
  • What if all elements are negative? → Kadane's still works — returns the least negative number
  • What about maximum product subarray? → Similar idea but track both min and max (negatives flip on multiplication)
  • Can you solve this with divide and conquer? → Yes, O(n log n) — split array, find max in left, right, and crossing middle

Product of Array Except Self — without division
▼
Problem: [1,2,3,4] → [24,12,8,6]. No division allowed!
def product_except_self_brute(nums):
    n = len(nums)
    result = []
    for i in range(n):
        product = 1
        for j in range(n):
            if j != i:
                product *= nums[j]
        result.append(product)
    return result
# Time: O(n²)
Time: O(n²)Space: O(1)
Key Insight: For each index i, answer = (product of all elements to LEFT of i) × (product of all elements to RIGHT of i). Build prefix array and suffix array.
def product_except_self(nums):
    n = len(nums)
    result = [1] * n
    
    # Pass 1: build prefix products (left to right)
    prefix = 1
    for i in range(n):
        result[i] = prefix
        prefix *= nums[i]
    # result = [1, 1, 2, 6]
    
    # Pass 2: multiply suffix products (right to left)
    suffix = 1
    for i in range(n-1, -1, -1):
        result[i] *= suffix
        suffix *= nums[i]
    # result = [24, 12, 8, 6] ✓
    
    return result
Time: O(n)Space: O(1) extra
Pattern: Prefix + Suffix trick. Use when you need "everything except current index." No extra arrays needed — reuse result array.
Cross Questions:
  • Why can't we use division? → What if there's a zero in the array? Division by zero breaks it
  • What if there are zeros in the array with division allowed? → Count zeros. If 2+ zeros → all zeros. If 1 zero → only that position has non-zero answer
  • How would you handle integer overflow? → Use long/BigInteger or modular arithmetic

Valid Anagram — Check if two strings are anagrams
▼
Problem: "anagram" and "nagaram" → True. "rat" and "car" → False
def is_anagram_sort(s, t):
    if len(s) != len(t):
        return False
    return sorted(s) == sorted(t)

# Time: O(n log n)  Space: O(n)
Time: O(n log n)Space: O(n)
Key Insight: Count frequency of each character in both strings. If all counts match → anagram.
from collections import Counter

def is_anagram(s, t):
    if len(s) != len(t):
        return False
    return Counter(s) == Counter(t)

# Manual version (no Counter):
def is_anagram_manual(s, t):
    if len(s) != len(t): return False
    count = {}
    for c in s:
        count[c] = count.get(c, 0) + 1
    for c in t:
        if c not in count or count[c] == 0:
            return False
        count[c] -= 1
    return True
Time: O(n)Space: O(1) — max 26 chars
Pattern: Character frequency counting with HashMap. Same pattern for group anagrams, first unique character problems.
Cross Questions:
  • What about Unicode characters (not just a-z)? → HashMap approach handles all Unicode. Array of 26 only works for lowercase English
  • Group Anagrams: given a list of words, group all anagrams together? → Use sorted word as key in HashMap
  • Is "ABC" anagram of "abc"? → Depends on requirements. Case-insensitive: convert both to lower first

Valid Palindrome — check if string reads same forwards and backwards
▼
Problem: "A man, a plan, a canal: Panama" → True (consider only alphanumeric)
def is_palindrome_simple(s):
    cleaned = ''.join(c.lower() for c in s if c.isalnum())
    return cleaned == cleaned[::-1]

# Time: O(n)  Space: O(n)
Time: O(n)Space: O(n)
Key Insight: Two pointers from both ends. Skip non-alphanumeric. Compare characters. If any mismatch → not palindrome.
def is_palindrome(s):
    left, right = 0, len(s) - 1
    
    while left < right:
        # Skip non-alphanumeric
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    
    return True
Time: O(n)Space: O(1) — in-place!
Pattern: Two pointers from both ends. Used for palindrome check, reverse operations, partitioning.
Cross Questions:
  • Longest Palindromic Substring? → Expand around center for each character: O(n²)
  • How many palindromic substrings in a string? → Same expand-around-center approach, count all expansions
  • Is a number a palindrome? → Convert to string, check. Or mathematical reversal without string conversion

3Sum — Find all triplets that sum to zero
▼
Problem: [-1,0,1,2,-1,-4] → [[-1,-1,2],[-1,0,1]]
def three_sum_brute(nums):
    result = set()
    n = len(nums)
    for i in range(n):
        for j in range(i+1, n):
            for k in range(j+1, n):
                if nums[i]+nums[j]+nums[k] == 0:
                    result.add(tuple(sorted([nums[i],nums[j],nums[k]])))
    return [list(t) for t in result]
# Time: O(n³)
Time: O(n³)Space: O(n)
Key Insight: Sort the array. Fix one element (outer loop), then use two pointers on the remaining portion to find pairs that sum to -nums[i]. Skip duplicates carefully.
def three_sum(nums):
    nums.sort()
    result = []
    
    for i in range(len(nums) - 2):
        # Skip duplicates for i
        if i > 0 and nums[i] == nums[i-1]:
            continue
        
        left, right = i + 1, len(nums) - 1
        
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            
            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                # Skip duplicates for left and right
                while left < right and nums[left] == nums[left+1]: left += 1
                while left < right and nums[right] == nums[right-1]: right -= 1
                left += 1
                right -= 1
            elif total < 0:
                left += 1   # need bigger sum
            else:
                right -= 1  # need smaller sum
    
    return result
Time: O(n²)Space: O(1)
Pattern: Sort + fix one element + two pointer for the rest. Works for k-Sum problems. Always handle duplicates by skipping repeated elements.
Cross Questions:
  • 3Sum Closest: find triplet with sum closest to target? → Same approach, track minimum difference instead of exact match
  • 4Sum? → Add one more outer loop, O(n³)
  • Why does sorting help here? → Enables two-pointer which requires sorted order. Also makes duplicate skipping easy.
  • Why can't we use HashSet instead of two pointer? → We can! O(n²) with HashSet for the inner pair, but two pointer is cleaner and uses O(1) space

Container with Most Water
▼
Problem: [1,8,6,2,5,4,8,3,7] → 49 (lines at index 1 and 8)
def max_area_brute(height):
    max_water = 0
    n = len(height)
    for i in range(n):
        for j in range(i+1, n):
            water = min(height[i], height[j]) * (j - i)
            max_water = max(max_water, water)
    return max_water
# Time: O(n²)
Time: O(n²)Space: O(1)
Key Insight: Start with widest container (left=0, right=end). Water = min(h[L],h[R]) × width. To try to find more water, move the shorter line inward (moving the taller line can never increase water).
def max_area(height):
    left, right = 0, len(height) - 1
    max_water = 0
    
    while left < right:
        width = right - left
        water = min(height[left], height[right]) * width
        max_water = max(max_water, water)
        
        # Move the shorter line (it's the bottleneck)
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    
    return max_water
Time: O(n)Space: O(1)
Greedy insight: Moving the taller line can only decrease width without increasing height. So always move the shorter one — it's the only hope for improvement.
Cross Questions:
  • Why move the shorter line and not the taller? → Moving the taller can only decrease min(h[L],h[R]) or keep it same, while width decreases. Always worse.
  • Trapping Rain Water (harder version)? → Different — water trapped above each bar, use stack or two-pointer with left_max/right_max arrays

Medium NagarroAmazonGoogle 🔥 Very Frequent
Longest Substring Without Repeating Characters
▼
Problem: "abcabcbb" → 3 ("abc"). "pwwkew" → 3 ("wke")
def length_of_longest_brute(s):
    max_len = 0
    n = len(s)
    for i in range(n):
        seen = set()
        for j in range(i, n):
            if s[j] in seen:
                break
            seen.add(s[j])
            max_len = max(max_len, j - i + 1)
    return max_len
# Time: O(n²)
Time: O(n²)Space: O(min(n,m))
Key Insight: Maintain a window [left, right]. Expand right. When duplicate found, shrink from left until duplicate is removed. HashMap stores last seen index of each char for O(1) jump.
def length_of_longest(s):
    char_index = {}  # char -> last seen index
    left = 0
    max_len = 0
    
    for right in range(len(s)):
        # If char seen and is inside current window
        if s[right] in char_index and char_index[s[right]] >= left:
            left = char_index[s[right]] + 1  # jump left past duplicate
        
        char_index[s[right]] = right  # update last seen
        max_len = max(max_len, right - left + 1)
    
    return max_len

# "abcabcbb"
# right=0: a→{a:0}, len=1
# right=3: a seen at 0, left=1, len=3 (bca)
# right=4: b seen at 1, left=2, len=3 (cab)...
Time: O(n)Space: O(min(n,charset))
Variable Sliding Window Template:
left=0, window={}
for right in range(n): add s[right] to window
while window invalid: remove s[left], left++
update max_len
Cross Questions:
  • What if we allow at most K repeating characters? → Track frequency in window, shrink when any char freq > k
  • Longest substring with at most 2 distinct characters? → Similar: shrink window when distinct chars > 2
  • Minimum window substring containing all chars of T? → Same sliding window, but shrink to minimize rather than maximize

Maximum Sum Subarray of Size K (Fixed Window)
▼
Problem: [2,1,5,1,3,2], k=3 → 9 (subarray [5,1,3])
def max_sum_brute(arr, k):
    max_sum = 0
    for i in range(len(arr) - k + 1):
        window_sum = sum(arr[i:i+k])
        max_sum = max(max_sum, window_sum)
    return max_sum
# Time: O(n*k)
Time: O(n×k)Space: O(1)
Key Insight: Slide the window by adding the new right element and removing the leftmost element. Avoid recalculating entire sum each time.
def max_sum_sliding(arr, k):
    # Build first window
    window_sum = sum(arr[:k])
    max_sum = window_sum
    
    # Slide: add right, remove left
    for i in range(k, len(arr)):
        window_sum += arr[i]        # add new right
        window_sum -= arr[i - k]    # remove old left
        max_sum = max(max_sum, window_sum)
    
    return max_sum

# [2,1,5,1,3,2], k=3
# Initial: 2+1+5=8
# slide: 8+1-2=7, 7+3-1=9(max), 9+2-3=8 → 9 ✓
Time: O(n)Space: O(1)
Fixed Window Template: Build first window of size k. Then slide: window += arr[right], window -= arr[right-k].
Cross Questions:
  • What if k is larger than array length? → Return 0 or raise error — handle edge case first
  • Average of all subarrays of size k? → Same sliding window, divide sum by k each step
  • Find first negative number in every window of size k? → Use a deque to track negatives within the window

Valid Parentheses — check if brackets are balanced
▼
Problem: "()" → True. "()[]{}" → True. "(]" → False. "([)]" → False

There's really only one clean approach — the stack:

  • Open brackets → push to stack
  • Close bracket → check if top of stack matches
  • If mismatch or stack empty → invalid
  • At end, stack must be empty
def is_valid(s):
    stack = []
    mapping = {')': '(', '}': '{', ']': '['}
    
    for char in s:
        if char in '([{':
            stack.append(char)  # push opening bracket
        else:
            # closing bracket: check stack
            if not stack or stack[-1] != mapping[char]:
                return False
            stack.pop()
    
    return len(stack) == 0  # stack must be empty

# "([)]": push (, push [, close ) needs ( but top is [ → False ✓
# "()[{}]": push (, close )→pop(, push [, push {, close }→pop{, close ]→pop[ → True ✓
Time: O(n)Space: O(n)
Stack Pattern: Whenever you need to match or track the most recent open element — use a stack. This pattern applies to: HTML tag validation, arithmetic expression evaluation, undo operations.
Cross Questions:
  • What if we have only one type of bracket? → Counter: +1 for open, -1 for close. Invalid if counter < 0 at any point or != 0 at end
  • Minimum additions to make string valid? → Count unmatched opens and unmatched closes at end
  • Generate all valid parentheses combinations for n pairs? → Backtracking recursion
  • How would you implement a stack from scratch? → Use a list with append() and pop()

Next Greater Element — for each element find next greater on right
▼
Problem: [4,5,2,25] → [5,25,25,-1]. For each element, find the next element that is greater.
def next_greater_brute(nums):
    n = len(nums)
    result = [-1] * n
    for i in range(n):
        for j in range(i+1, n):
            if nums[j] > nums[i]:
                result[i] = nums[j]
                break
    return result
# Time: O(n²)
Time: O(n²)Space: O(1)
Key Insight: Monotonic Decreasing Stack. Walk right to left. Stack keeps elements waiting for their "next greater." When we see a larger element, it's the answer for everything in the stack that is smaller.
def next_greater(nums):
    n = len(nums)
    result = [-1] * n
    stack = []  # stores indices, decreasing from bottom
    
    for i in range(n - 1, -1, -1):  # right to left
        # Pop elements smaller than current
        while stack and stack[-1] <= nums[i]:
            stack.pop()
        
        # Top of stack (if exists) is next greater
        if stack:
            result[i] = stack[-1]
        
        stack.append(nums[i])
    
    return result

# [4,5,2,25]: process right to left
# i=3: stack=[], result[3]=-1, push 25 → [25]
# i=2: 25>2, result[2]=25, push 2 → [25,2]
# i=1: pop 2(≤5), 25>5, result[1]=25, push 5 → [25,5]
# i=0: pop 5(≤4)? No! 5>4, result[0]=5 → [5,25,25,-1] ✓
Time: O(n)Space: O(n)
Monotonic Stack Pattern: Keep stack in sorted order (increasing or decreasing). When new element violates order → pop and process. Used for: Next Greater/Smaller, Largest Rectangle in Histogram, Daily Temperatures.
Cross Questions:
  • What about circular array (wrap around)? → Run the same loop twice (0 to 2n), use index % n
  • Previous Greater Element? → Same but walk left to right, stack stays decreasing
  • Daily Temperatures (days until warmer)? → Same pattern but store indices, answer = current_index - stack_index

Implement Queue using Two Stacks
▼
Problem: Implement enqueue and dequeue using only two stacks (no deque/list methods).
# Approach 1: Costly enqueue
class QueueV1:
    def __init__(self):
        self.s1, self.s2 = [], []
    
    def enqueue(self, x):  # O(n)
        while self.s1:
            self.s2.append(self.s1.pop())
        self.s1.append(x)
        while self.s2:
            self.s1.append(self.s2.pop())
    
    def dequeue(self):     # O(1)
        return self.s1.pop() if self.s1 else -1
Enqueue: O(n)Dequeue: O(1)
Key Insight: Lazy transfer — only move items from s1 to s2 when s2 is empty. This gives amortized O(1) for both operations.
class MyQueue:
    def __init__(self):
        self.inbox = []   # for push
        self.outbox = []  # for pop
    
    def push(self, x):   # O(1)
        self.inbox.append(x)
    
    def pop(self):       # amortized O(1)
        self._transfer()
        return self.outbox.pop()
    
    def peek(self):      # amortized O(1)
        self._transfer()
        return self.outbox[-1]
    
    def empty(self):
        return not self.inbox and not self.outbox
    
    def _transfer(self):
        # Only transfer when outbox is empty
        if not self.outbox:
            while self.inbox:
                self.outbox.append(self.inbox.pop())

# push(1),push(2),push(3) → inbox=[1,2,3]
# pop() → transfer: outbox=[3,2,1] → pop 1 ✓
# pop() → outbox=[3,2] → pop 2 ✓
# push(4) → inbox=[4], outbox=[3]
# pop() → outbox not empty → pop 3 ✓
Amortized O(1) both opsSpace: O(n)
Amortized Analysis: Each element is pushed and popped from each stack at most once. Total operations = 2n, so average per operation = O(1). Interviewers love when you explain amortized complexity.
Cross Questions:
  • Implement Stack using two Queues? → Costly push: move all elements from q2 to q1 after each push
  • What is amortized O(1)? → Average cost per operation over many operations. Some ops are expensive but occur rarely, so average stays low.
  • LRU Cache? → Doubly linked list + HashMap. Both are O(1). Asked frequently at senior levels.

Binary Search — Find element in sorted array
▼
Problem: Sorted array [-1,0,3,5,9,12], target=9 → return index 4
def search_linear(nums, target):
    for i, num in enumerate(nums):
        if num == target:
            return i
    return -1
# Time: O(n)  Space: O(1)
Time: O(n)Space: O(1)
Key Insight: Compare target to middle element. If smaller → search left half. If larger → search right half. Eliminate half the search space each step.
def binary_search(nums, target):
    low, high = 0, len(nums) - 1
    
    while low <= high:              # NOTE: <= not <
        mid = low + (high - low) // 2  # avoids overflow
        
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            low = mid + 1           # search right half
        else:
            high = mid - 1          # search left half
    
    return -1  # not found

# COMMON BUGS TO AVOID:
# 1. Use <= in while condition (not <)

def find_min(nums):
    low, high = 0, len(nums) - 1
    
    while low < high:
        mid = low + (high - low) // 2
        
        if nums[mid] > nums[high]:
            low = mid + 1   # min is in right half
        else:
            high = mid      # min is in left half (could be mid)
    
    return nums[low]

    stack = []
    curr = head
    while curr:
        stack.append(curr.val)
        curr = curr.next
    curr = head
    while stack:
        curr.val = stack.pop()
        curr = curr.next
    return head
# Time: O(n)  Space: O(n)

Key Insight: Three pointers: prev, curr, next. Walk through list reversing each link. Draw this on paper — it's 3 pointer movements per step.
def reverse_list(head):
    prev = None
    curr = head
    
    while curr:
        next_node = curr.next  # save next before we overwrite
        curr.next = prev       # reverse the link
        prev = curr            # move prev forward
        curr = next_node       # move curr forward
    
    return prev  # prev is now the new head

# Step by step: 1→2→3→None, prev=None
# Step 1: save(2), 1.next=None, prev=1, curr=2
# Step 2: save(3), 2.next=1, prev=2, curr=3
# Step 3: save(None), 3.next=2, prev=3, curr=None
# return prev=3 → 3→2→1 ✓

Detect Cycle in Linked List — Floyd's Algorithm
▼
Problem: Given a linked list, return True if it has a cycle, False otherwise.
def has_cycle_hashset(head):
    seen = set()
    curr = head
    while curr:
        if id(curr) in seen:
            return True
        seen.add(id(curr))
        curr = curr.next
    return False
# Time: O(n)  Space: O(n)
Time: O(n)Space: O(n)
Floyd's Cycle Detection: Slow pointer moves 1 step, fast moves 2 steps. If there's a cycle, fast will eventually lap slow and they'll meet. Like two runners on a circular track.
def has_cycle(head):
    slow = head
    fast = head
    
    while fast and fast.next:
        slow = slow.next        # move 1 step
        fast = fast.next.next   # move 2 steps
        
        if slow == fast:        # they met → cycle!
            return True
    
    return False  # fast reached end → no cycle

# Why does this work?
# If cycle exists: fast enters cycle first.
# Relative speed of fast vs slow = 1 step/iteration.
# Fast will always catch slow within (cycle_length) iterations.
# They MUST meet — they can't skip each other (gap decreases by 1 each step)
Time: O(n)Space: O(1) — no extra space!
Fast/Slow Pointer: Used for cycle detection, finding middle of list, Nth node from end. Two runners at different speeds — one laps the other if running in circles.
Cross Questions:
  • Find the start of the cycle? → When slow and fast meet, move one to head. Advance both 1 step at a time. Where they meet again = cycle start.
  • Find length of the cycle? → Once they meet in cycle, keep slow still, advance fast until it comes back. Count steps.
  • Find middle of linked list? → Slow/fast pointers. When fast reaches end, slow is at middle.

def merge_two_lists(l1, l2):
    dummy = ListNode(0)  # dummy head to simplify code
    curr = dummy
    
    while l1 and l2:
        if l1.val <= l2.val:
            curr.next = l1
            l1 = l1.next
        else:
            curr.next = l2
            l2 = l2.next
        curr = curr.next
    
    # Attach remaining nodes
    curr.next = l1 if l1 else l2
    
    return dummy.next

Tree Traversals — Inorder, Preorder, Postorder
▼
Problem: Given a binary tree, return nodes in inorder (left-root-right), preorder (root-left-right), postorder (left-right-root) order.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val; self.left = left; self.right = right

def inorder(root):      # Left → Root → Right
    if not root: return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def preorder(root):     # Root → Left → Right
    if not root: return []
    return [root.val] + preorder(root.left) + preorder(root.right)

def postorder(root):    # Left → Right → Root
    if not root: return []
    return postorder(root.left) + postorder(root.right) + [root.val]

# Inorder of BST = sorted order ← very important!
Time: O(n)Space: O(h) — h=height
Iterative Inorder — often asked in interviews:
def inorder_iterative(root):
    result = []
    stack = []
    curr = root
    
    while curr or stack:
        # Go as far left as possible
        while curr:
            stack.append(curr)
            curr = curr.left
        
        # Process node
        curr = stack.pop()
        result.append(curr.val)
        
        # Move to right subtree
        curr = curr.right
    
    return result

# Level Order (BFS) — also very commonly asked:
from collections import deque

def level_order(root):
    if not root: return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):  # process one level at a time
            node = queue.popleft()
            level.append(node.val)
            if node.left: queue.append(node.left)
            if node.right: queue.append(node.right)
        result.append(level)
    return result
Time: O(n)Space: O(w) — w=max width
Key fact: Inorder of BST gives sorted sequence. This is how you validate a BST and how you find kth smallest element.
Cross Questions:
  • What is the inorder traversal of a BST? → Gives nodes in ascending sorted order
  • How do you find height of a binary tree? → Recursive: 1 + max(height(left), height(right))
  • Check if binary tree is balanced? → Height of left subtree and right subtree differ by at most 1, recursively
  • Diameter of binary tree (longest path between any two nodes)? → For each node: diameter = left_height + right_height. Return max.

Lowest Common Ancestor (LCA) of Binary Tree
▼
Problem: Find lowest common ancestor of nodes p and q in a binary tree.
def lca_brute(root, p, q):
    def find_path(node, target, path):
        if not node: return False
        path.append(node)
        if node == target: return True
        if find_path(node.left, target, path): return True
        if find_path(node.right, target, path): return True
        path.pop()
        return False
    
    path_p, path_q = [], []
    find_path(root, p, path_p)
    find_path(root, q, path_q)
    
    lca = None
    for a, b in zip(path_p, path_q):
        if a == b: lca = a
    return lca
# Time: O(n)  Space: O(n)
Time: O(n)Space: O(n)
Key Insight: DFS returning nodes. If current node is p or q → return it. LCA is where left and right both return non-null (found one target in each subtree).
def lowest_common_ancestor(root, p, q):
    if not root:
        return None
    
    # If current node is p or q, it's the LCA (or ancestor of LCA)
    if root == p or root == q:
        return root
    
    # Search in left and right subtrees
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    
    # If both sides returned something → current node is LCA
    if left and right:
        return root
    
    # Otherwise, return whichever side found something
    return left if left else right

# Why this works:
# If p is in left subtree and q in right subtree → root is LCA
# If both in same subtree → that subtree's LCA is returned up
Time: O(n)Space: O(h)
DFS Return Pattern: Return the "found" node upward. When both left and right return non-null, you've found the split point = LCA. Elegant and O(n) single pass.
Cross Questions:
  • LCA in a BST (not general tree)? → Simpler: if both p,q < root.val → go left. If both > → go right. Else root is LCA.
  • What if one node doesn't exist in the tree? → Modify to return (found_p, found_q, lca) tuple
  • LCA with parent pointers? → Walk up from both nodes, track visited. First common = LCA. Like finding intersection of two linked lists.

def is_valid_bst(root):
    def validate(node, min_val, max_val):
        if not node:
            return True
        
        # Node must be strictly within (min_val, max_val)
        if node.val <= min_val or node.val >= max_val:
            return False
        
        # Left subtree: upper bound = current val
        # Right subtree: lower bound = current val
        return (validate(node.left, min_val, node.val) and
                validate(node.right, node.val, max_val))
    
    return validate(root, float('-inf'), float('inf'))

# Alternative: Inorder traversal — should be strictly increasing
def is_valid_bst_inorder(root):
    prev = [float('-inf')]
    def inorder(node):
        if not node: return True
        if not inorder(node.left): return False
        if node.val <= prev[0]: return False
        prev[0] = node.val
        return inorder(node.right)
    return inorder(root)
Time: O(n)Space: O(h)

Kth Largest Element in an Array
▼
Problem: [3,2,1,5,6,4], k=2 → 5 (2nd largest)
def find_kth_largest_sort(nums, k):
    nums.sort(reverse=True)
    return nums[k-1]
# Time: O(n log n)
Time: O(n log n)Space: O(1)
Key Insight: Maintain a min-heap of size k. When heap size exceeds k, remove the smallest. At the end, the top of the heap = kth largest.
import heapq

def find_kth_largest(nums, k):
    min_heap = []
    
    for num in nums:
        heapq.heappush(min_heap, num)
        
        if len(min_heap) > k:
            heapq.heappop(min_heap)  # remove smallest
    
    return min_heap[0]  # top = kth largest

# Why min-heap? We want to KEEP the k largest elements.
# min-heap's top is the SMALLEST of those k largest.
# = kth largest overall!

# [3,2,1,5,6,4], k=2:
# heap after all: [5,6] (min-heap → [5,6])
# top = 5 = 2nd largest ✓

# Bonus: heapq in Python is min-heap by default
# For max-heap: negate values or use [-x for x in nums]
Time: O(n log k)Space: O(k)
Heap Pattern: "Find top K elements" → min-heap of size K. "Find K smallest" → max-heap of size K (negate values). Heap size never exceeds K.
Cross Questions:
  • What if k is equal to n? → Just return the minimum of the array
  • Top K frequent elements? → Count frequencies, then use min-heap on (frequency, element). O(n log k)
  • Kth smallest in a sorted matrix? → Use min-heap, push first element of each row, pop k times
  • QuickSelect approach for Kth largest? → Average O(n) but O(n²) worst case. Heap is O(n log k) guaranteed.
  • Median of a stream? → Two heaps: max-heap for lower half, min-heap for upper half. Balance them.

Heap O(n log k) approach — better when k << n:
import heapq
from collections import Counter

def top_k_frequent(nums, k):
    count = Counter(nums)
    
    # Min-heap of (frequency, element), size k
    heap = []
    for num, freq in count.items():
        heapq.heappush(heap, (freq, num))
        if len(heap) > k:
            heapq.heappop(heap)  # remove least frequent
    
    return [num for freq, num in heap]

# Bucket Sort O(n) approach — optimal!
def top_k_bucket(nums, k):
    count = Counter(nums)
    # Bucket index = frequency
    buckets = [[] for _ in range(len(nums) + 1)]
    for num, freq in count.items():
        buckets[freq].append(num)
    
    result = []
    for i in range(len(buckets) - 1, 0, -1):  # high freq first
        result.extend(buckets[i])
        if len(result) >= k:
            return result[:k]
    return result
Heap: O(n log k) | Bucket: O(n)Space: O(n)
Bucket Sort insight: When values are bounded (frequency can't exceed n), use bucket sort for O(n). Frequency as index → each bucket contains elements with that frequency.

  • Sort Characters By Frequency? → Same approach but return a string: char * frequency, sorted by decreasing frequency
  • Why is bucket sort O(n) here when sort is O(n log n)? → Bucket sort doesn't use comparisons. It uses the value as an index. Valid when value range is bounded.

Find Median from Data Stream
▼
Problem: Design data structure that supports addNum and findMedian. Median of a stream of numbers.
class MedianFinder_Brute:

Key Insight: Maintain two heaps: max-heap for lower half, min-heap for upper half. Keep them balanced (size difference ≤ 1). Median = top of larger heap or average of both tops.
import heapq

class MedianFinder:
    def __init__(self):
        self.small = []  # max-heap (negate for Python min-heap)
        self.large = []  # min-heap
    
    def addNum(self, num):
        # Push to max-heap (lower half)
        heapq.heappush(self.small, -num)
        
        # Balance: largest in small must be <= smallest in large
        if self.small and self.large and (-self.small[0] > self.large[0]):
            heapq.heappush(self.large, -heapq.heappop(self.small))
        
        # Balance sizes (differ by at most 1)
        if len(self.small) > len(self.large) + 1:
            heapq.heappush(self.large, -heapq.heappop(self.small))
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))
    
    def findMedian(self):
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2
addNum: O(log n)findMedian: O(1)
Two Heap Pattern: max-heap for lower half (always ≤ min-heap for upper half). After each insert, rebalance so size differs by at most 1. Median = top of larger heap or average of both tops.
Cross Questions:
  • How do you handle even vs odd total numbers? → Even: average of both tops. Odd: top of the larger heap.
  • Why Python's heapq is min-heap? → Push negative values to simulate max-heap. Remember to negate when reading.
  • Sliding window median? → Much harder — need ordered set or two heaps with lazy deletion
